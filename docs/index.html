Streaming analytics research prototype

Online gaming data.
Processed in real time.

A reproducible event-stream platform that sends simulated game activity through Apache Kafka, validates and stores it in PostgreSQL, and serves analytics to a live dashboard.

View project on GitHub Run the prototype

This GitHub Pages site is a static project overview. The Streamlit dashboard and FastAPI service run with the local Docker Compose stack; this page does not claim to host a live data feed.

One event stream, end to end

Domain topics keep game activity organized while the consumer validates, cleans, and persists each event before committing its offset.

01 / GENERATE

Gaming simulator

Player, score, purchase, session, and achievement events.

02 / STREAM

Kafka on KRaft

Keyed events in domain-specific topics plus a dead-letter topic.

03 / PROCESS

Validate & deduplicate

Python consumer normalizes records and isolates invalid messages.

04 / STORE

PostgreSQL

Transactional event storage and relational gaming facts.

05 / VISUALIZE

API & dashboard

FastAPI analytics feed an auto-refreshing Streamlit dashboard.

Designed for data quality

Reliability behavior is explicit, testable, and documented rather than hidden behind success-shaped fallbacks.

Contract validation

Timezone-aware timestamps, supported event types, and event-specific fields are checked before persistence.

Duplicate protection

Stable event identifiers and a database uniqueness constraint make redelivery safe for stored effects.

Dead-letter handling

Invalid payloads retain their rejection reason and are acknowledged by Kafka before offsets advance.

Operational analytics

Track active players, scores, sessions, purchases, pipeline throughput, latency, and consumer lag.

Automated refresh

The dashboard queries the API on a refresh interval and reports API or broker failures explicitly.

Reproducible inputs

Seeded event generation and documented setup help repeat local tests and benchmark trials.

Measured carefully

Run it locally

Requires Python 3.13 and Docker Desktop with Compose v2.

1 / Prepare

py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

2 / Start the pipeline

docker compose up --build

Compose starts the Kafka KRaft broker, PostgreSQL, producer, consumer, API, and dashboard. Open the dashboard at http://localhost:8501 and API docs at http://localhost:8000/docs. Do not expose the development credentials or plaintext listeners to the Internet.
